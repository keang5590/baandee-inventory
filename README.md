# บ้านดี — ระบบคลังอุปกรณ์ออกบูธ (Inventory Web App)

เว็บแอพสำหรับจัดการสต็อกอุปกรณ์ออกบูธ + สร้างรายการออกบูธ + หมวดค่าใช้จ่าย
ทำตามดีไซน์จากภาพตัวอย่างที่ให้มา ออกแบบให้ deploy ขึ้นออนไลน์ให้ทีมใช้งานร่วมกันได้จริง

## สแต็กที่ใช้ (และทำไมถึงเลือกแบบนี้)

| ส่วน | เทคโนโลยี | เหตุผล |
|---|---|---|
| Backend | Node.js + Express | ง่าย เรียนรู้เร็ว มี community ใหญ่ |
| ฐานข้อมูล | PostgreSQL (ผ่านไลบรารี `pg`) | ข้อมูลอยู่ถาวรแม้ deploy ใหม่ รองรับหลายคนใช้พร้อมกันจริง ต่างจาก SQLite ที่เก็บเป็นไฟล์บนดิสก์ของเซิร์ฟเวอร์เดียว (พังง่ายเวลา deploy ใหม่บน cloud เพราะดิสก์ชั่วคราว) |
| Frontend | HTML + CSS + JavaScript ล้วน (ไม่มี framework) | เห็นการทำงานของเว็บแบบตรงไปตรงมา เหมาะกับการเริ่มเรียนรู้ |

> โปรเจกต์นี้เคยเริ่มจาก SQLite (ไฟล์เดียว รันง่ายสุด) แล้วย้ายมา PostgreSQL ตอนที่ตัดสินใจ
> จะ deploy ให้คนอื่นใช้งานร่วมกันจริง — ถ้าใครอยากรู้ว่าต่างกันตรงไหน ลองเทียบโค้ดใน `db/init.js`
> กับ commit ก่อนหน้าดู เป็นตัวอย่างที่ดีของ "เริ่มง่ายๆ ก่อน ค่อยอัปเกรดตอนจำเป็น"

## วิธีรันในเครื่องตัวเอง (local development)

ต้องมี [Node.js](https://nodejs.org) เวอร์ชัน 18 ขึ้นไป และ [Docker](https://www.docker.com/) (สำหรับรัน Postgres)

```bash
cd baandee-inventory
cp .env.example .env       # ตั้งค่าตัวแปรแวดล้อม (ค่าเริ่มต้นใช้ได้เลย)
docker compose up -d       # เปิดฐานข้อมูล PostgreSQL ในเครื่อง
npm install                 # ติดตั้ง dependencies
npm start                   # รันเซิร์ฟเวอร์
```

แล้วเปิดเบราว์เซอร์ไปที่ **http://localhost:3000**

ครั้งแรกที่รัน ระบบจะสร้างตารางและเติมข้อมูลตัวอย่างให้อัตโนมัติ
(อุปกรณ์ 8 ชิ้น, งานออกบูธ 1 งาน, หมวดค่าใช้จ่าย 7 หมวด) — รันซ้ำได้เรื่อยๆ ไม่เติมซ้ำซ้อน
ถ้าอยากเริ่มฐานข้อมูลใหม่ทั้งหมด: `docker compose down -v` แล้ว `docker compose up -d` ใหม่

อยากให้เซิร์ฟเวอร์รีสตาร์ทอัตโนมัติทุกครั้งที่แก้โค้ด ใช้ `npm run dev` แทน `npm start`

ไม่มี Docker ก็ใช้ PostgreSQL ที่ติดตั้งในเครื่องอยู่แล้วได้ แค่แก้ `DATABASE_URL` ใน `.env`
ให้ชี้ไปที่ฐานข้อมูลนั้นแทน

## วิธี deploy ขึ้นออนไลน์ (ให้คนอื่นใช้งานได้)

โปรเจกต์นี้เตรียมไฟล์สำหรับ deploy ขึ้น [Render](https://render.com) ไว้ให้แล้ว 2 แบบ:

**แบบที่ 1 — ผ่าน Render Blueprint (แนะนำ ง่ายสุด)**
1. สร้าง repository บน GitHub แล้ว push โค้ดทั้งโฟลเดอร์นี้ขึ้นไป
2. เข้า [Render Dashboard](https://dashboard.render.com/) → New → **Blueprint** → เลือก repo นี้
3. Render จะอ่านไฟล์ `render.yaml` แล้วสร้าง Web Service + ฐานข้อมูล PostgreSQL ให้อัตโนมัติ
   พร้อมเชื่อม `DATABASE_URL` ให้เองโดยไม่ต้องตั้งค่าอะไรเพิ่ม
4. รอ build เสร็จ แล้วจะได้ URL สาธารณะ เช่น `https://baandee-inventory.onrender.com`
   ส่งลิงก์นี้ให้ใครก็เข้าใช้งานได้เลย

**แบบที่ 2 — ผ่าน Docker**
ใช้ `Dockerfile` ที่เตรียมไว้ deploy กับแพลตฟอร์มที่รับ Docker image ได้ (Render, Railway,
Fly.io, หรือ VPS ของตัวเอง) แค่ตั้งค่า environment variable `DATABASE_URL` ให้ชี้ไปที่
ฐานข้อมูล Postgres ที่ใช้งานจริง

> เพลตฟอร์มอื่นที่ไม่ใช่ Render ก็ใช้แนวทางเดียวกันได้ (Railway, Fly.io ฯลฯ) แค่สร้าง Postgres
> database แล้วตั้งค่า `DATABASE_URL` ให้ web service ชี้มาที่ database นั้น

## โครงสร้างโปรเจกต์

```
baandee-inventory/
├── server.js            ← จุดเริ่มต้น: ตั้ง Express, ประกาศ API ทุก endpoint
├── db/
│   └── init.js           ← เชื่อมต่อ PostgreSQL, สร้างตาราง, เติมข้อมูลตัวอย่าง
├── public/                ← ไฟล์หน้าเว็บ (ฝั่ง frontend)
│   ├── index.html         ← โครงหน้าเว็บ, แท็บต่างๆ, โมดัลต่างๆ
│   ├── style.css           ← ธีมสีเหลือง/ดำแบบในภาพตัวอย่าง
│   └── app.js               ← ตรรกะฝั่งหน้าเว็บ: เรียก API, สลับแท็บ, วาดการ์ด/ตาราง
├── docker-compose.yml      ← รัน Postgres ในเครื่องตอน dev
├── Dockerfile               ← สำหรับ deploy แบบ container
├── render.yaml               ← Render Blueprint (สร้าง web service + database ให้อัตโนมัติ)
├── .env.example               ← ตัวอย่างตัวแปรแวดล้อมที่ต้องตั้งค่า
└── package.json
```

**หลักการทำงานคร่าวๆ:** เบราว์เซอร์เปิด `index.html` → `app.js` ยิง `fetch()` ไปหา
`server.js` ที่ endpoint เช่น `/api/equipment` → `server.js` ไปอ่าน/เขียนข้อมูลใน
PostgreSQL ผ่าน connection pool ใน `db/init.js` → ส่งผลลัพธ์กลับเป็น JSON → `app.js`
เอาไปวาดเป็นการ์ด/ตารางบนหน้าจอ นี่คือรูปแบบพื้นฐานของเว็บแอพเกือบทุกตัว
(frontend ↔ API ↔ database)

## รายการ API ทั้งหมด

| Method | Endpoint | คำอธิบาย |
|---|---|---|
| GET | `/api/health` | เช็คว่าเซิร์ฟเวอร์และฐานข้อมูลเชื่อมต่อได้ (ใช้ตรวจสอบตอน deploy) |
| GET | `/api/categories` | หมวดหมู่อุปกรณ์ |
| GET | `/api/equipment?q=&category_id=&status=` | รายการอุปกรณ์ (ค้นหา/กรองได้) |
| POST | `/api/equipment` | เพิ่มอุปกรณ์ใหม่ |
| PATCH | `/api/equipment/:id` | แก้ไขอุปกรณ์ |
| DELETE | `/api/equipment/:id` | ลบอุปกรณ์ |
| GET / POST | `/api/events` | งานออกบูธ (รายการออกบูธ) |
| GET | `/api/bookings` | รายการจองทั้งหมด (พร้อมรายการอุปกรณ์ในแต่ละใบจอง) |
| POST | `/api/bookings` | สร้างใบจองใหม่ |
| PATCH | `/api/bookings/:id` | เปลี่ยนสถานะใบจอง |
| GET / POST | `/api/expense-categories` | หมวดค่าใช้จ่าย |
| DELETE | `/api/expense-categories/:id` | ลบหมวดค่าใช้จ่าย |
| GET | `/api/expenses?event_id=&category_id=` | รายการค่าใช้จ่าย |
| POST | `/api/expenses` | บันทึกค่าใช้จ่ายใหม่ |
| DELETE | `/api/expenses/:id` | ลบรายการค่าใช้จ่าย |
| GET | `/api/expenses/summary?event_id=` | ยอดรวมค่าใช้จ่ายแยกตามหมวด |

## แท็บที่ทำงานได้จริงตอนนี้

- **รายการออกบูธของฉัน / + สร้างรายการออกบูธใหม่** — สร้างงานออกบูธใหม่ (ชื่องาน, สถานที่,
  วันที่) บันทึกลงฐานข้อมูลจริง งานที่สร้างล่าสุดจะกลายเป็น "งานที่ใช้งานอยู่" ทันที
  หรือจะกลับไปเลือกงานเก่าให้เป็นงานที่ใช้งานอยู่ก็ได้จากการ์ดในแท็บนี้
- **อุปกรณ์ทั้งหมด** — ค้นหา, กรองหมวดหมู่/สถานะ, เลือกจำนวน, ใส่ตะกร้า, กด "ถัดไป" เพื่อสร้าง
  ใบจองจริงผูกกับงานออกบูธที่กำลังใช้งานอยู่
- **หมวดค่าใช้จ่าย** — การ์ดสรุปยอดต่อหมวด, ตารางรายการค่าใช้จ่าย, เพิ่มหมวดหมู่เอง,
  บันทึก/ลบรายการค่าใช้จ่าย, กรองตามงานออกบูธ
- **การจองอุปกรณ์** — แสดงใบจองทั้งหมดที่สร้างไว้
- **หน้าหลัก** — สรุปภาพรวม (จำนวนอุปกรณ์, สต็อกรวม, จำนวนการจอง, ยอดค่าใช้จ่ายรวม)

แท็บอื่นๆ ในเมนู (คลังอุปกรณ์, ประวัติการใช้งาน, รายงาน, ตั้งค่า) ใส่ไว้เป็นหน้าว่างเตรียมต่อยอด
— โครง API ด้านบนรองรับพอที่จะเอาไปต่อได้เลย

## แนวทางต่อยอด (ขั้นต่อไปที่แนะนำให้ลองทำเอง)

1. **ระบบล็อกอิน** — ตอนนี้ผู้ใช้ "Tanatorn Y." เป็นข้อมูล hardcode ในหน้าเว็บ ลองเพิ่มตาราง `users`
   และหน้า login จริง เพื่อให้รู้ว่าใครสร้างรายการออกบูธ/จองอุปกรณ์บ้าง
2. **อัปโหลดรูปอุปกรณ์** — ตอนนี้การ์ดอุปกรณ์ใช้ไอคอน emoji แทนรูป ลองเพิ่ม endpoint
   อัปโหลดไฟล์รูป (เช่นด้วย `multer`) แล้วเก็บ path ไว้ในคอลัมน์ `image_url` ที่มีอยู่แล้ว
3. **ตัดสต็อกจริงตอนจอง** — ตอนนี้แค่เปลี่ยนสถานะเป็น `reserved` ลองทำให้ `stock_qty`
   ลดลงจริงตามจำนวนที่จอง และคืนสต็อกเมื่อยกเลิกใบจอง
4. **กราฟค่าใช้จ่าย** — แท็บหมวดค่าใช้จ่ายมี endpoint `/api/expenses/summary` พร้อมอยู่แล้ว
   ลองต่อกับไลบรารีกราฟ เช่น Chart.js เพื่อวาดเป็นกราฟวงกลม/แท่ง
5. **ลบ/แก้ไขรายการออกบูธ** — ตอนนี้ทำได้แค่สร้างใหม่ ลองเพิ่ม endpoint `PATCH`/`DELETE`
   สำหรับ `/api/events/:id`
